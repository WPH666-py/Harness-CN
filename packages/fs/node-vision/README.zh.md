# @deepseek-ai/dsh-node-vision

[English](README.md) | 中文

## 概述

面向模型的图像检查与像素操作，基于 [sharp](https://sharp.pixelplumbing.com/)，无需 Python 运行时，也不使用外部视觉提供方。

理解由模型自己完成：`read_image` 把一张图片展示给它，而这些工具负责度量与变换。每个产出像素的工具都以 `image` 内容块返回结果，因此模型检查的是它刚产出的内容，而不是轻信一段摘要。

## 工具

| 工具 | 产出 | 用途 |
|---|---|---|
| `vision_info` | 文本 | 尺寸、格式、字节大小、通道、alpha、色彩空间。 |
| `vision_crop` | 图像 | 保留一个矩形；该矩形必须位于源图之内。 |
| `vision_resize` | 图像 | 按宽度、高度或倍数缩放；只给出其中一维时保持宽高比。 |
| `vision_colors` | 文本 | 以十六进制值给出主色，以及每种主色覆盖的像素占比。 |
| `vision_diff` | 文本，可选图像 | 像素比较，给出计数与差值；`visualize` 返回一张标出变化像素的图片。 |

每个产出工具还接受 `output_path`，并通过 `ctx.fs.writeBytes` 把同样的字节保存到该文件，因此挂载的后端会像约束一次文本写入那样约束这次写入。

坐标是以磁盘上文件左上角为原点度量的像素。当附件存储接受源格式时，结果按源自身的格式编码，因此一次 JPEG 裁剪仍是 JPEG。

## 要求

- 当前模型路由必须声明 `image` 输入。每次执行都会解析发起调用会话所路由到的提供方与模型，否则以具名错误拒绝，因此该失败是可见的，而不是静默的。
- 已挂载的 `attachments` 服务。没有它这些工具根本不会注册，因为产出的图像没有可持久存放的位置。

## 模型体验

每次调用增加一条工具结果。产出型调用携带一段简短摘要加一张图像，因此它的成本是输出的像素，而不是输入的像素。`vision_info` 与 `vision_colors` 只增加文本。

没有任何工具会把图像字节回显进 transcript（文本记录），也没有任何工具会把源图像重新读入模型上下文，因此一连串像素操作不会累积原图的图片。产出工具附上的图像就是该操作在调用方所要求尺寸下的结果；若要在后续步骤读取之前缩小大幅结果，`vision_resize` 就是途径。

提示词可缓存性不受影响：本包不贡献任何提示词段落，也不贡献系统提示词文本。

## 已知限制与延期工作

- **写入型调用没有 `sandbox_permissions` 参数**：`output_path` 经由 `ctx.fs.writeBytes`，未按调用提供策略时由 `fs-sandbox` 解析会话自身的策略，因此只读会话会拒绝该写入。这些工具没有提供的，是 `write` 工具所公开的按调用升权，因此需要写入工作区之外的调用方必须更改会话模式，而不能给某一次调用单独打上标记。
- **`vision_diff` 把 alpha 作为第四个通道比较**：仅透明度的变化也会被报告为差异，这通常是需要的，但不可配置。
- **不同尺寸的图像按其左上角重叠区域比较**：报告会写明两个尺寸并说明比较是部分的，因此结果绝不会在无提示的情况下不完整；若改为拒绝，则「它们是否不同」就得不到回答。
- **没有旋转、合成、格式转换或矢量描摹**：裁剪、缩放、调色板提取与像素比较覆盖了模型检查与调整图像所需的操作；其余操作属于有明确需求的调用方。
