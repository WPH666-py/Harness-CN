feat(desktop): work on a remote host, and stage the workbench in three steps

The workbench tree only ever showed the local workspace, and pressing 使用 in
服务器管理 switched the host without switching the view, so a remote session
looked like a local one with an empty editor. Clicking a change card in the
remote panel then took the whole page down: the plugin rendered DiffBlock
without a dictionary, and the toolbar read `labels.copy` off undefined.

- The tree follows the current host. It polls the plugin's host list and, while
  a host is current, lists, reads and saves through that host's routes; with no
  host it behaves exactly as before.
- The tree header names the host and grows a search box that asks the host for
  a filename (`GET /hosts/:id/search`), so finding a file no longer means
  walking directories one request at a time. `rg --files` answers when the host
  has it, `find -type f -name` otherwise.
- The presentation now cycles 对话 → 工作站 → IDE 全屏. The full-screen stage
  folds the sidebar, the conversation column and the folder button away, keeps
  a 回到对话 pill inside the seat, and drops back to the conversation stage on
  the way out.
- Code blocks and diffs fall back to English labels when the owner passes none,
  so a plugin that forgets the dictionary renders instead of blanking the page.
- `apps/desktop/scripts/lib` is source here: the patch scripts import it and
  `lib/` stays build output everywhere else.
